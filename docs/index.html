Guide

react-native-razorpay-customui-checkout

A React Native wrapper around Razorpay's native Custom UI Checkout SDK, for apps that build their own payment UI instead of using Razorpay's hosted checkout screen.

Status: this package starts as a fork of react-native-customui (same Gradle/CocoaPods native dependencies). Native Android/iOS sources are currently a direct copy of upstream so the build config keeps working as-is; the JS/TS layer is being rewritten incrementally to fix issues described below.

Why this fork exists

The upstream JS bridge has a few sharp edges this package addresses:

  • Global event teardown. Upstream's removeSubscriptions() tears down every registered native listener whenever any single SDK call resolves, which corrupts concurrent or retried requests.
  • Unsettled init promise. initRazorpay()'s JS promise never settles on some SDK versions.
  • No cancellation/timeout/retry. Discovery calls like getPaymentMethods and getAppsWhichSupportUPI have no built-in cancellation, timeout, or retry support.

Guide

Installation

Install the package, then link the native iOS pod. Android is linked automatically via autolinking.

sh
npm install react-native-razorpay-customui-checkout
cd ios && pod install

Or with Yarn:

sh
yarn add react-native-razorpay-customui-checkout
cd ios && pod install
The native dependency razorpay-customui-pod (~> 2.1.4) is pulled in automatically via CocoaPods on iOS — no manual pod entry needed.

Guide

Quick start

Initialize the SDK with your Razorpay key once (e.g. on app start or before opening checkout), then call open() with your order details.

js
import Razorpay from 'react-native-razorpay-customui-checkout';

// 1. Initialize once with your key
await Razorpay.initRazorpay('rzp_test_xxxxxxxxxxxx');

// 2. Open checkout for a specific payment method / order
try {
  const payment = await Razorpay.open({
    key_id: 'rzp_test_xxxxxxxxxxxx',
    amount: '50000',        // amount in the smallest currency unit (paise)
    currency: 'INR',
    order_id: 'order_DBJOWzybf0sJbb',
    method: 'upi',
    vpa: 'success@razorpay',
    email: 'customer@example.com',
    contact: '9999999999',
  });

  console.log('Payment succeeded:', payment.razorpay_payment_id);
} catch (error) {
  console.log('Payment failed:', error);
}

Guide

Error handling

Every discovery/action method that depends on the native SDK — everything except the local card utilities — requires initRazorpay(key) to have resolved first. Calling one before init rejects immediately with:

json
{ "error": "Please initialize razorpay first by calling Razorpay.init(key)" }

open() rejects with a RazorpayError shape on payment failure or cancellation:

ts
type RazorpayError = {
  code?: number | string;
  description?: string;
  error?: {
    code?: string;
    description?: string;
    source?: string;
    step?: string;
    reason?: string;
  };
};
Because event listeners are torn down globally when any call resolves (a known upstream issue this fork is progressively fixing — see Overview), avoid firing multiple native calls concurrently until the JS rewrite lands.

Guide

Migration notes

If you're coming from react-native-customui, the API surface is intentionally close to a drop-in:

  • Import path changes to react-native-razorpay-customui-checkout; the default export is still a Razorpay class with static methods.
  • isValidCardNumber, getCardsNetwork, and getCardNetworkLength now resolve entirely in JS (regex/BIN-prefix matching + Luhn checksum) instead of round-tripping to native code — they work even before initRazorpay() has run.
  • New named exports are available directly for card validation without going through the Razorpay class — see Named exports.

API reference

All methods below are static methods on the default Razorpay export, e.g. Razorpay.open(options).

initRazorpay(key)

async

Initializes the Razorpay native SDK with your API key. Must resolve before calling any other native-backed method.

Parameters

NameTypeRequiredDescription
keystringYesYour Razorpay key_id.

Returns

Promise<void>

js
await Razorpay.initRazorpay('rzp_test_xxxxxxxxxxxx');

open(options, successCallback?, errorCallback?)

async

Opens native checkout for the given options and resolves on payment success, or rejects on failure/cancellation. Callbacks are optional — if provided, they're used instead of the promise resolve/reject.

Parameters

NameTypeRequiredDescription
optionsRazorpayOpenOptionsYesOrder and payment method details. See types.
successCallback(data: RazorpaySuccess) => voidNoCalled instead of resolving the promise on success.
errorCallback(error: RazorpayError) => voidNoCalled instead of rejecting the promise on failure.

Returns

Promise<RazorpaySuccess>

js
const payment = await Razorpay.open({
  key_id: 'rzp_test_xxxxxxxxxxxx',
  amount: '50000',
  currency: 'INR',
  order_id: 'order_DBJOWzybf0sJbb',
  method: 'card',
  'card[name]': 'John Doe',
  'card[number]': '4111111111111111',
  'card[cvv]': '123',
  'card[expiry_month]': '12',
  'card[expiry_year]': '2028',
});

isValidVpa(vpaAddress)

async requires init

Validates a UPI VPA (Virtual Payment Address) against Razorpay's servers.

Parameters

NameTypeRequiredDescription

}

validateOptions(payload)

async requires init (Android)

Validates a checkout options payload before calling open(). On iOS this always resolves true without a native round trip; on Android it delegates to the native SDK and requires initRazorpay() first.

Parameters

NameTypeRequiredDescription
payloadRazorpayOpenOptionsYesThe same options object you intend to pass to open().

Returns

Promise<{ data: boolean }>

js
const { data: isValid } = await Razorpay.validateOptions(options);
if (isValid) {
  await Razorpay.open(options);
}

Reference

Card utilities

Card number/network/CVV validation runs entirely in JS via regex/BIN-prefix matching and a Luhn checksum — no native round trip, and no dependency on initRazorpay() having run. Network codes match Razorpay's own card_networks keys: AMEX, MC, VISA, RUPAY, MAES, JCB, DICL, UNP.

isValidCardNumber(cardNumber)

async local

Full validation: known network, correct digit length for that network, and a passing Luhn checksum.

Parameters

NameTypeRequiredDescription
cardNumberstringYesCard number, digits or formatted with spaces/dashes.

Returns

Promise<{ data: boolean }>

js
const { data: isValid } = await Razorpay.isValidCardNumber('4111 1111 1111 1111');

getCardsNetwork(cardNumber)

async local

Detects the card network from a (possibly partial) card number by BIN prefix, so it can be shown while the user is still typing.

Parameters

NameTypeRequiredDescription
cardNumberstringYesFull or partial card number.

Returns

Promise<{ data: string }> — one of the card network codes, or an empty string if unmatched.

js
const { data: network } = await Razorpay.getCardsNetwork('4111');
console.log(network); // "VISA"

getCardNetworkLength(networkName)

async local

Returns the longest valid digit length for a network, useful for an input's maxLength.

Parameters

NameTypeRequiredDescription
networkNamestringYesA card network code, e.g. "VISA".

Returns

Promise<{ data: number }> — 0 if the network is unknown.

js
const { data: maxLength } = await Razorpay.getCardNetworkLength('AMEX');
console.log(maxLength); // 15

Named exports

local, synchronous

The same card-validation logic is also available as plain synchronous named exports, without going through the Razorpay class:

js
import {
  detectCardNetwork,
  isCardNumberValid,
  getCardNetworkLength,
  isValidCardCvv,
  passesLuhnCheck,
  CARD_NETWORK_LENGTHS,
} from 'react-native-razorpay-customui-checkout';

detectCardNetwork('4111');           // 'VISA' | null
isCardNumberValid('4111111111111111'); // boolean
getCardNetworkLength('VISA');        // 16
isValidCardCvv('123', 'VISA');       // true — 4 digits required for 'AMEX', 3 otherwise
passesLuhnCheck('4111111111111111'); // boolean
CARD_NETWORK_LENGTHS.VISA;           // [13, 16, 19]
ExportSignatureDescription
detectCardNetwork(cardNumber: string) => CardNetwork | nullSame BIN-prefix detection used internally.
isCardNumberValid(cardNumber: string) => booleanAlias for the underlying isValidCardNumber function.
getCardNetworkLength(network: string) => numberLongest valid digit length, or 0.
isValidCardCvv(cvv: string, network: CardNetwork | string | null) => booleanAmex requires a 4-digit CVV; every other network requires 3.
passesLuhnCheck(digits: string) => booleanRaw Luhn checksum, no network/length checks.
CARD_NETWORK_LENGTHSRecord<CardNetwork, number[]>Table of valid digit lengths per network.
